How it's built

Rulebook

Twelve rules in plain English, modeled on partner programs I've run. Eligibility, direct-sales conflicts, first to register, protection windows, escalation.

MCP server

Tools over CRM and partner data. The tools do the date math and fuzzy matching, so the model spends its effort on judgment.

Claude agent

One conversation per registration. Partner input is treated as untrusted. When unsure it escalates, and if it ever fails to decide, the default is escalate, never approve.

Eval

38 labeled cases and a rules-engine baseline, rerun every time the policy changes. A policy change created the one model miss, and the eval caught it.

Where this goes

Deal registration is a form because people are the system of record. When agents can read the call notes, emails and partner manager notes that already exist, a partner's involvement can be shown from evidence instead of claimed on a form.

What changes

  • No data entry. Registrations and co-sell activity assemble themselves from the conversations that already happen.
  • Credit that follows evidence. The SI that shaped the architecture and the reseller that transacted both get credit for what they did.
  • Partner recommendations. Which partner belongs on which deal, to win it and to keep the ecosystem healthy over time.

What has to stay true

  • Protection still comes first. Registration is a promise that lets partners invest before a deal exists.
  • Published policy, explained decisions, a way to appeal. People set the policy and handle exceptions. The agent applies it.
  • Fair evidence. We record our own team's calls, not the partners'. That bias has to be designed for.
  • Expect gaming. Once notes drive credit, partners write notes to win credit.
